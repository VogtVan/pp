# AUTHOR-MIGRATE — an existing system moves in

Work through the hall's cycle; what is yours here:

1. **Map** the existing system in three columns: what pp takes over (the turn's discipline, the
   record of operations, the closing choices), what stays for now, what dies -- each death naming
   the mechanism that replaces it.
2. **Keep the essence** of each piece, never its prose: what does it make TRUE, what does it
   FORBID (a law), what does it PRODUCE (a step and its form)?
3. **Check the collisions** against what this instance serves (the catalogue, `tools.md`): a name
   already taken, a role already held -- extend the existing piece, never add a twin.
4. **Place** each piece: a PROC when an order of steps must hold, a SKILL served on demand, a
   SCRIPT beside its contract when the work is deterministic.
5. **Sequence** the steps so the replacement is in force before the old way falls; each step
   says how the operator will see it done.

The member, the rules and the offers are crafts of their own: open them from here with
`./pp <key> -open <craft>` when the sheet reaches them, and say each hand-over.
