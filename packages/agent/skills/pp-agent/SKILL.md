# `pp-agent` — the house's hand over its agents

## The hand, in one breath

The house's hand over its agents -- an agent is an instance anywhere under the house that borrows its machine, and it IS its path (`ag1`, `rep1/ag1`); `add <path>` gives it birth, `run` wakes it for ONE exchange by a harness in its non-interactive mode and keeps its answer, `chat` holds a conversation -- one run from a message to the next, the messages read on stdin; under `--json` a flow of events, each naming its voice --, `list`, `status`, `responses` and `messages` read. `name` names a run, `exchanges` and `stats` read one, `--json` on `list` and `status` give the post its faces. The one writer of responses.jsonl, messages.jsonl and names.jsonl; the one launcher of a harness.


## Entities

| Entity | Storage | Fields |
|---|---|---|
| Agent | `<house>/<path>/.pp`, an instance that borrows the house's machine, no door, no wiring | its PATH relative to the house, slugs joined by `/` (`ag1`, `rep1/ag1`) -- its identity in every verb and record; its runs, its own trace |
| The house | `<house>/.pp` itself, addressed as the agent `.` | its own runs, its doors and wiring; its face counts its runs of the post alone (those the house conducts as their principal), never its host's conversations (`run-unconducted`); no material (`work-on-house`) |
| Message | `<house>/.pp/.sys/records/messages.jsonl`, one object per line, append-only (`purge` alone removes a run's lines) | `at` (ISO 8601 UTC, to the second), `from` (the house's slug), `to` (the agent's path), `run` (the key), `message` (the text sent), `policy` (the model, the budget and the permission regime given, as the face judged them -- a budget a number, never the typed text; `{}` when none) |
| Response | `<house>/.pp/.sys/records/responses.jsonl`, one object per line, append-only (`purge` alone removes a run's lines) | `at`, `agent` (its path), `run` (always: the house opens the run before the harness plays), `index` (1 at the run's first response), `response` (the composition of `words`, written once: their texts in order, joined by a blank line, a blank one dropped, nothing added -- `null` when the model said nothing), `cost_usd` (the SUM of the wake-up's launches, each the difference of the cumuls the provider reports; `null` when it reports none), `session_cost_usd` (the provider's cumul for the session after the wake-up), `launches` (the launches of the harness the wake-up played), `denials` (the permissions it was denied, every launch), `error` (what failed, as the harness names it, `null` on success), `harness_rc` (the last launch's exit code), `words` (every words of the exchange's launches, `[{launch, text}]` in order -- the matter `response` is composed of; the pieces a host streams are made whole by the engine's reader before they reach the house: one text per words), `model` and `effort` (the policy played, `null` when none was asked) |
| Session | `<house>/.pp/.sys/records/sessions.jsonl`, one object per line, append-only (`purge` alone removes a run's lines) | `at`, `agent` (its path), `run`, `provider` (the provider launched, `null` under `--harness`), `session` (the identity the provider gave) -- a line at the run's opening, one more when the provider gives another identity; the run's last line holds its session |
| Run | the agent's slot, read by the engine's face (`persistence.awaits`); its trace for the label of the stack alone | `parked` when the stack waits for the principal's message (the passage over: AWAIT); `standing` when a step pends, the block it stands on beside; the exchanges completed |
| Name | `<house>/.pp/.sys/records/names.jsonl`, one object per line, append-only (`purge` alone removes a run's lines) | `at`, `agent`, `run`, `name` -- the name `name` gave the run; a run's last line holds its name |
| Flow | `<house>/.pp/.sys/records/flows/<digest of the agent's path>/<key>.jsonl`, one file per run, one object per line, append-only (`purge` removes the file) | every event an exchange of the run said, in its order -- `opened`, `principal`, `conduction` (its text whole), `tool`, `tool-result`, `thinking`, `words`, `agent`, the steps (`kind: step`, `event`), then `response` and `verdict` -- each the object `chat --json` says (`kind`, `at`, `run`, its fields), written by the KEEPER `exchange` wraps its `say` with, for every exchange: `run`, `start`, `chat`, conducted or bare; the conversation's own events (`ready`, `waiting`, `refused`, `policy`, `conduct`, `package`, `closed`) are not kept; the file is appended WHILE the launch plays, every 0.2 s, by the one process that holds the wake lock: a reader may follow it line by line as the run goes |

## Commands

The house's console carries the verb: `./pp agent <verb> …` at the house's root. An
agent of the house reaches the verbs through the conductor: `./pp <key> -s pp-agent <verb> …`.

| Form | Effect |
|---|---|
| `add <path> [--type <package>]` | Gives birth to the agent at `<path>` (`./pp agent add rep1/ag1`) by the engine's install: an instance that BORROWS the house's machine, no door, the seed of an interactive instance, its slug the path's last segment; says `pp-agent: <path> born`. `--type` is reserved: `type-unsupported`. |
| `run <path> (--message <text> \| --message-file <path>) [--model <m>] [--max-budget-usd <n>] [--permissions auto\|strict\|bypass] [--effort low\|medium\|high\|xhigh\|max] [--launches <n>] [--new \| --run <key>] [--provider <name>] [--harness <command>] [--work <repo> [--base <ref>]] [--door <document>] [--documents <dir>] [--package <name>=on\|off]... [--tag <id>] [--on-end <command>] [--json] [--quiet] [--heartbeat <seconds>] [--dry-run]` | `--package`, repeated, names the packages the run plays: judged before anything (`package-invalid`, `package-base`, `package-unpinned` -- a package the agent's instance does not pin, switched on; switched off, it asks nothing and is left out), each switch played on the run under the mark before the first launch by the waiting list `chat` keeps, said on stderr and kept in the run's flow, `--dry-run` saying `package <name> on|off`. ONE exchange, as a message typed in a session, CONDUCTED BY THIS SCRIPT -- the run's principal. The message is required (`message-missing`; `--message-file -` reads stdin). Without `--run`, once everything is judged, this script plays `-new "<message>"` on the agent's instance under the principal's mark (`PP_CONDUCTED_BY_PRINCIPAL=true`, on its own calls to pp alone), reads the run's key on the output's first line and holds the launcher's lock (`session-<key>.wake.lock` beside the slot) from there to the records' write. Then the LOOP: the harness is launched in `<path>/`, in a session of its provider -- opened at the first launch, resumed (`PP_AGENT_SESSION` under `--harness`) at the next ones --, on the PROMPT written on its standard input: the first launch carries `[message from your principal]`, the message, a blank line, then pp's whole output; every later launch pp's output alone. After each launch this script reads the run: an output HELD by the agent's value call, a chunk waiting, or a block to advance -> its own marked bare call serves or advances, and the harness is launched again on what came back; a run PARKED (its passage over) with nothing held ends the loop, the response composed of the words of its launches. A run the harness opened meanwhile (a `-new` it typed at the parked run) is a STRAY run: `stray run <key>` on stderr, counted at the verdict, never forgotten. `--launches <n>` bounds the launches of one wake-up (24 unless said; a whole number at least 1, else `launches-invalid`): reached, `launches-spent`, the last response kept, the run left standing, exit 2. `--run <key>` resumes the run (`run-unknown`; `session-missing` when no session is recorded, `provider-mismatch` under another provider -- nothing launched): parked, the marked `<key> "<message>"` opens the exchange (traced `prompt`); standing (a wake-up died mid-loop), the loop goes on from where it stands -- the message under its head, then what the run holds or the block that stands -- and the verdict says `standing resumed`; renewed by an upgrade, the marked call reopens it under its key. The harness: `--harness <command>` runs that command, its output read in the GRAMMAR of the provider `--provider <name>` names beside it (`grammar-missing` without it: nothing opened, nothing written); else `--provider <name>`, else the ONE provider the house is wired with; the line is composed by `conductor.adapters.launch` -- `(argv, env, stdin)` -- with the MARBLE OF THE MODE (`.sys/system.common.md`), the house as `wiring`, the policy and the session; its environment never carries the principal's mark. The agent calls pp for its values alone (`./pp <key> -`): a bare call it types is refused by the engine (`principal-advances`), a `-new` it types mid-exchange opens nothing. After the loop, the answer -- read by the adapter of the grammar (`conductor.adapters.answer`); this script reads no field of a harness's output itself -- must carry the session identity (`session-missing`: nothing is kept); then `messages.jsonl`, `responses.jsonl` (`cost_usd` the SUM of the launches' costs, each read in the scope the adapter of the grammar declares, its `COST` -- `session`: the difference between the cumul it reports and the cumul before it; `launch`: as reported; `None`: no cost --; `session_cost_usd` the run's cumul in that session; `launches` the launches) and, when the identity is new for the run, `sessions.jsonl` gain their line. A first launch that fails without a word keeps nothing; a later one keeps the last response with the error. Then stdout carries what was kept -- the response's text, each of its lines opening on `::` (blanks before included) prefixed with a backslash, since the console takes such a line as an order to pp (`::push`, `::clear`, `::mount`) and an agent's words never give pp an order; with `--json`, one object: the response's record line plus `session` and `state` (`parked`, `standing`, `stopped`) -- and stderr the verdict line: `pp-agent: <path> · run <key> · exchange <n> · parked\|standing\|stopped · harness rc <c> [· <cost> USD] [· <spent>/<cap> USD cap] · <n> launch(es) [· <n> stray run(s)] [· standing resumed] [· after an interruption]`. A failure that kept a response renders it on stdout before its refusal; nothing is printed when nothing was kept. While the harness plays, the run's trace is followed -- read, never written -- and each step it records is said on stderr as it happens, one line each: `[HH:MM:SS] <key> · opened`, the stack of a block served (`· parked` when it waits for the principal), `answer` (a production received), `refused <code>`, `repair <document>`, `skill <name>`, `compacted`; this script's own steps the same way: `launch <n> · <c> chars · <cost> USD`, `served held output`, `served chunk`, `advanced`, `stray run <key>`; under `--json` each is one JSON object (`at`, `run`, `event`, its fields). After `--heartbeat` seconds without a step (60 by default, a whole number at least 1, else `heartbeat-invalid`), a line says `no event for <n>s`, and again at every such stretch. `--quiet` says none of it; the verdict and the refusals stay. Exit 0 when the harness exited 0 AND the run parked with nothing held AND a response with text was recorded; exit 2 otherwise, the reason on stderr. `--dry-run` says the marked `-new "<message>"` (the resume's `<key> "<message>"` with `--run`, `PP_DOOR=<document>` on it under `--door`, `PP_PROMPT_CAP=<n>` on it when the run's adapter declares a cap -- its `CAPS` for the policy's model, its `CAP` for any --: the outputs served at the prompt are cut under it, whole up to it), the composed line, its variables and the working directory, then `--- stdin (<n> chars) ---` and the head of the first prompt -- the message under its head, then where pp's output goes; launches nothing, opens no run, writes nothing. Every judgment comes before the opening and the launch -- the run, its session and provider, its material's repository, the composed line: a refusal leaves the run as the last wake-up left it (the MARK in its wake lock file -- the hour of the last wake-up, the first line of its message, the responses the run had then -- untouched) and an opening refused opens no run. `--effort` names the model's effort, judged by the face and spelled by the adapter (`policy-unsupported` where it cannot). `--max-budget-usd <n>` is the BUDGET CAP of the RUN -- what it spends over all its exchanges and their launches, conducted or bare: the sum of its responses' `cost_usd` plus the launches of the exchange under way. Before EVERY launch the remainder is computed: none left, nothing is launched -- before an exchange `budget-spent` refuses it (nothing recorded, the run as it was), between two launches the loop stops (the last response kept, the run standing, the reason `budget-spent`); some left, it is handed to the launch's policy as `max_budget_usd` where the adapter spells the key (`SPELLS`), dropped where it does not. The cap is never exact: a launch goes past the remainder by what the provider's own bound lets through, as its adapter documents it, by one launch where the adapter spells none. Under an adapter whose `COST` is None a cap refuses `budget-unmeasured` before anything. A resume keeps the cap of the run's last message; a flag or a `set` replaces it. When other runs of the agent play, the prompt opens on the NEIGHBOURS line, `[runs under way: <key> since HH:MM « <head> » · …]` -- each wake lock held, the local hour of its mark and the first line of its message (60 characters) --, then a blank line and the message under its head. `--work <repo> [--base <ref>]` gives the run its MATERIAL: a clone under `<path>/work/<key>` on the branch `agent/<path>/<key>` cut from the repository's current branch (or `--base`), made under the house's lock for that repository once the run is opened, the prompt opening on the material's head, `PP_WORKDIR`, `PP_CONSOLE` and the agent's git identity in the environment, the branch pushed back after the harness and kept at `workdirs.jsonl`; a resume reopens the run's own clone. `--door <document>` names the ENTRY of an opening (carried by `PP_DOOR` on this script's `-new`, opened as a CALL above the boot). `--documents <dir>` -- absolute, or relative to the house's directory -- gives the run its ROOT of documents (carried by `PP_DOCUMENTS` on this script's `-new` alone, kept by the engine at the run; the harness and every other call never inherit it). `--tag <id>` is written with the message; `--on-end <command>` plays by the shell once the records are written and the wake lock released (`PP_AGENT_NAME`, `PP_AGENT_RUN`, `PP_AGENT_STATE`). |
| `chat <path> [--run <key>] [--model <m>] [--max-budget-usd <n>] [--permissions auto\|strict\|bypass] [--effort low\|medium\|high\|xhigh\|max] [--launches <n>] [--provider <name>] [--harness <command>] [--work <repo> [--base <ref>]] [--door <document>] [--documents <dir>] [--package <name>=on\|off]... [--json] [--quiet] [--heartbeat <seconds>]` | `--package` seeds the waiting list before any message (`ready.pending`). A CONVERSATION at the foreground, conducted by this script -- the verb `agent` is declared `tty: true`: the console hands this script its three streams, nothing captured. The messages are read on stdin, one per line: a line ending on a backslash goes on with the next (the backslash taken out, the line break kept), an empty line sends nothing. Each message is ONE exchange -- the same exchange `run` plays, the same code (`exchange`) -- of ONE run held from a message to the next with its session and its wake lock: the first message opens the run, `--run <key>` resumes one instead (`run-unknown`, `session-missing`, `provider-mismatch`, `run-busy` judged before any message is read), every later message resumes it; a `run`, a `start` or any other wake-up on that run refuses `run-busy` while the conversation lives. `--work` and `--door` play at the opening alone (`door-on-resume` with `--run`). After each exchange: the response on stdout as `run` prints it (`::` behind a backslash), the verdict line on stderr; an exchange that ends badly (`launches-spent`, `harness rc <c>`, the passage not over) says why on stderr and the conversation GOES ON -- the run stands, the next message takes it up (`standing resumed`). The records are `run`'s: one line of `messages.jsonl` and one of `responses.jsonl` per message (`index` growing on the run), one of `sessions.jsonl` when the identity is new. A SIGINT to this script during an exchange ends the harness (SIGTERM, SIGKILL after 5 s; `run` does the same, no orphan) and the exchange is said `interrupted`: the words of the finished launches kept with the error `interrupted`, nothing when none had finished; the run stands, the conversation waits for the next message; the interruption is kept in the MARK of the run's wake lock (`interrupted: true`, no record touched), and the next wake-up of the run -- this conversation's or another process's (`chat --run`, `run --run`) -- opens its first prompt on `[interrupted by your principal]` before the message's head, says `· after an interruption` at its verdict and clears the mark. A SIGINT while waiting for a message, or the end of stdin, closes the conversation: the lock released, exit 0; `chat --run <key>` or `run --run <key>` takes the run up. `--message`, `--message-file`, `--dry-run`, `--tag`, `--on-end` and `--new` refuse `flag-unsupported`. Under `--json` the conversation is a FLOW. stdin carries one JSON object per line, read by a thread of its own so that a command arrives during an exchange too: `{"kind": "message", "text": "…"}` (one exchange), `{"kind": "stop"}` (the exchange under way ends as on a SIGINT: `interrupted`; nothing when none plays), `{"kind": "quit"}` (the conversation closes after the exchange under way), `{"kind": "set", "model": …, "max_budget_usd": …, "permissions": …, "effort": …}` (the policy of the NEXT launches, one key or several, judged with the rest of the policy at once: held, said by `policy`; `provider` refuses `provider-fixed`, a value that does not parse `policy-invalid`, a key nobody knows `policy-unknown`, a permission regime the run's provider does not spell `policy-unsupported` -- `refused`, the policy unchanged; what else the provider cannot spell refuses at the next launch, `policy-unsupported`), `{"kind": "conduct", "on": false|true}` (off: the next exchanges are BARE -- one launch on the session, the message under its head and nothing of pp, no call of pp, the run unmoved, both record lines `conducted: false`; on: the conduction back at the next message; said by `conduct`), `{"kind": "package", "name": …, "on": false|true}` (the engine's `-disable`/`-enable` played on the run under the mark, the block it prints not served; a switch the run cannot take yet -- before the run is opened, or while the package holds the run's view, the engine's `package-in-flight` -- WAITS in the conversation's list, played again before every launch until the engine takes it; said by `package` with `pending: true` while it waits, `pending: false` once it plays or when the run plays that state already, which cancels a wait; any other refusal of the engine relayed as `refused` with its code and `detail`; the list lives in this process); `conduct` before the run is opened refuses `run-missing`; a line that does not read, or a kind nobody knows, is `refused` (`command-unreadable`, `command-unknown`) and the flow goes on. stdout carries one JSON object per line, each with `kind`, `at` (ISO 8601 UTC) and `run`; the kinds are a CLOSED list: `ready` {agent, resumed, provider, policy, packages, cap, conducted, pending} (said ONCE, first, before the first `waiting` and any message: the run as the conversation judged it -- its key in the event's `run` under `--run`, `null` at an opening; the packages as SETTINGS switch them when no run is open yet); `opened` {agent, exchange, resumed, standing, provider, policy, packages, cap, conducted, interrupted} (a run opened or taken up, the provider -- `harness` for a caller's command --, the policy in force, the packages pinned beyond the base `{name, on}` as the run plays them, the cap `{set, applied}` -- the agent's `max_harness_tool_output` and the cap its outputs are cut under: the cap this script names on its marked calls from what the run's adapter declares (`CAPS` by the model's name as `--model` gives it, else `CAP`), else at least 200 000, the floor of a principal's cap --, `conducted: false` on a bare exchange, `interrupted: true` when the run's last wake-up was interrupted); `principal` {exchange, text} -- the message as sent; `conduction` {exchange, launch, text, chars, blocks, left} -- pp's output served to the harness at that launch, ALONE (no head, no message, no neighbours line): what a reader may hide; `chars` its length, `blocks` the `{stack, command, wait}` of each block the run's trace wrote since the conduction before -- the outputs it serves, read from the trace, never from the text --, `left` the characters still to come when it is a piece of a cut output; under `--quiet` `chars` alone; `agent` {exchange, launch, cost_usd} -- the end of that launch and its cost, no text: the model's text is its `words`; never recorded; what the launch does, said WHILE it plays (every complete line the harness printed read by the engine's reader of the adapter, `conductor.adapters.reader`, every 0.2 s), always before its `agent` and never recorded -- `tool` {exchange, launch, id, name, title, shell, input, pp} (a call of a tool; `pp` true when `shell` calls the agent's console, `./pp` or its absolute path), `tool-result` {exchange, launch, id, content, error}, `thinking` {exchange, launch, text or tokens}, `words` {exchange, launch, text} (the one source of the model's text, each whole: the pieces a host streams are joined by the engine's reader, `conductor.adapters.reader`, before anything is said); a line the adapter refuses is a `step` `refusal` {code `events-malformed`, detail} and the launch goes on; `run`, `start` and the text mode say none of these four; `step` {event, …} -- a step of the run or of the house in the grammar `run --json` says (`new`, `reopened`, `block` {stack, wait}, `answer`, `refusal` {code}, `repair`, `gesture`, `compacted`, `launch` {launch, chars, cost_usd}, `served`, `advanced`, `stray`, `quiet`), the only kind `--quiet` silences; `response` -- the `responses.jsonl` line plus `session` and `state`; `verdict` {exchange, state, harness_rc, cost_usd, launches, strays, standing_resumed, kept, reason} -- `state` `unconducted` for a bare exchange, `reason` when the exchange did not end well; `waiting` (a command is awaited); `refused` {code, line, detail} (`detail` the engine's words, for a `package` it refused); `policy` {provider, policy} (after a `set` that held: the policy of the next launch); `conduct` {on}; `package` {name, on, pending, packages}; `closed`. stderr is silent from the first command on. |
| `start <path> (--message … \| --message-file …) [the flags of run] [--tag <id>] [--on-end <command>]` | The same exchange DETACHED: the child (`run … --detached`, its own session) holds the wake lock and reports ONE JSON line `{"key", "pid"}`, printed here at once; its stderr goes to the wake log `session-<key>.wake.log` beside the lock. A refusal before the report is relayed, exit 2. `--json` and `--dry-run` refuse `flag-unsupported`. |
| `wait <path> <key> [--timeout <seconds>]` | Waits for the run's wake lock to be free (looked at, never taken), then prints the run's last response as `run` does; `wake-dead` when the last launch added no response, `wait-timeout` past the bound. |
| `result <path> <key>` | The run's last response at once; `wake-running` while a wake-up plays and has not answered, `wake-dead`, `result-missing`. |
| `workdirs [<path>]` | One line per material: agent, run, branch, repository, commits ahead of the base, clean or dirty, pushed or not, the run's state. |
| `prune <path> <key> [--force]` | Removes the run's clone and writes `pruned` -- the run is never resumed again (`workdir-missing`); `run-busy` while a wake-up plays the run, `workdir-unpushed` over commits the repository has not received (`--force` removes them), `workdir-unknown` without a material. |
| `purge <path> (<key> … \| --before <YYYY-MM-DD>) [--yes] [--force] [--json]` | Removes FOR GOOD what the house keeps of runs of the agent, then has the engine remove what the agent keeps of them -- each record by its writer. The runs: the keys named (`run-unknown` for a key neither the records nor the agent knows), or every run of the agent whose newest line in the records and newest trace at the agent are older than the date (`purge-invalid` for a date that does not read); `.` purges the house's runs of the post alone (`run-unconducted` for its host's). Without `--yes` it SAYS what it would remove -- one line per run, its lines by record, its files at the agent and their bytes (the engine's `-purge -json`), its clone -- and writes nothing. All or nothing: each run's wake lock is tried without waiting (`run-busy`: a wake-up or a conversation holds it), a clone with commits the repository has not received refuses `workdir-unpushed` (`--force` removes them), then `./pp -purge <keys> --yes -json` plays on the agent's instance (its `call-busy` relayed) -- only then is each record rewritten without the runs' lines, under its lock, each flow file and each clone removed. `--json` one object `{dry, agent, runs: [{key, lines, files, bytes, workdir, flow}], lines, files, bytes}`. Before anything else -- dry or not -- the engine asks the guardian of the family `agent-run` for each run (`events.guarded` on `agent-run:<path>/<key>`): a package that declares itself the guardian may keep a run, `run-held` relaying its reason; no guardian declared, nothing plays. |
| `verify` | The VERIFIER of the family `agent-run` this package declares (`agent-run: {verify: pp-agent}`), the engine's call: the vector `agent-run:<path>/<key>` on stdin -- rc 0 when the house or the agent keeps something of the run (a line of the records, a file of the engine, its flow), `run-unknown` otherwise, `family-foreign` for another family. Reads only. |
| `flow <path> <key> [--exchange <n>] [--json]` | The flow the run's exchanges kept: under `--json` each line as kept -- the very object `chat --json` said --, otherwise one line per event, `HH:MM:SS  #<exchange>  <kind or step event>  <first line of its text>` (`::` behind a backslash); `--exchange <n>` keeps the n-th exchange from its `opened` on; `run-unknown` for a key no run wears; a run older than agent 0.22.0 has none. `--exchange <n>` counts the n-th `opened` of the flow -- the rank `exchanges` gives the message, never the number the run counts (plan fixes2). |
| `list [--json]` | One line per agent -- every instance under the house's workspace that borrows its machine, at any depth: `<path> · <n> run(s) · <n> running · <n> response(s)`; under `--json` one object per agent, `{agent, runs, running, responses, weight}` (`weight` the sum of its runs'), the house itself FIRST (`agent: "."`, its runs of the post alone). |
| `status <path>` | One line per run, the run whose last line is the latest first, a run without a line last -- `run <key> · <n> exchange(s) · parked \| standing on <stack> · session <id> (<provider> \| harness) \| no session` --, the responses, the providers the house is wired with. |
| `status <path> --json` | One object per run, in the order of the text -- `{agent, run, name, exchanges, state, stack, session, provider, cost_usd, launches, responses, first_message, first_at, last_at, policy, budget, context, weight}`: `state` the one that prevails (`running` while a wake-up plays, `dead` when the last one added no response, else `parked` or `standing`), `stack` the block it stands on, `name` what `name` gave (`""` otherwise), the records summed (`cost_usd` the sum of the responses' costs or `null`, `launches` their sum, `first_message` and `first_at` the run's first message, `last_at` the hour of the last line of either record); a launch whose agent opened no run as `exchanges 0`; `policy` the policy of the run's last message (`{}` when none was sent); `budget` `{cap, spent, left}` under its budget cap, `null` without; `context` the run's context reduced (`null` without a `flow`); `weight` `{lines, files, bytes, flow}` -- what `purge` would count of the run: the lines of the five records that carry it, the files the engine keeps of it and their bytes, the bytes of its flow file (`null` without one), the same numbers as `purge <path> <key> --json` without `--yes`; then one object `{agent, providers, last, weight}` (`weight` the sum of the runs') -- `last` the provider of the agent's last session (`harness` for a caller's command) and the policy of its last message, `{provider, policy}`, `null` when it was never sent one. |
| `name <path> <key> [<name>]` | Names the run: one line `{at, agent, run, name}` to `names.jsonl`, the last line of a run winning; `run-unknown` on a key no run wears, `name-invalid` for anything but one line of 1 to 60 printable characters (the blanks around taken off): what a user types, accents and punctuation kept as typed. Without `<name>`, says the current one or `(no name)`. The name shows at `status --json`, never in the text. |
| `exchanges <path> <key> [--json]` | The run's history, one line per message in order: `#<n>  <at>  <message, first line> -> <response, first line> [· <cost> USD · <n> launch(es)]`, `(no response)` when none came; under `--json` one object per exchange `{agent, run, index, at, message, response, cost_usd, launches, error, harness_rc, conducted, words, model, effort}` (`conducted` false for a bare exchange; `words`, `model` and `effort` as the response line keeps them) -- each message of the run (`index` its rank) paired with the response that answers it, by the hour of the two records (a response kept after it and before the next message; an exchange that kept nothing leaves its message unanswered), the response's fields `null` when none came. `run-unknown`. |
| `stats <path> <key> [--json]` | The detail of the run's conduction: the engine's own `-stats <key>` played on the agent's instance and relayed as it is; under `--json` one object `{agent, run, cost_usd, launches, exchanges, conduction}` where `conduction` is the run's object of `-stats <key> -json`, untouched. `run-unknown`; `stats-unreadable` when the engine rendered no JSON. |
| `providers [--json]` | Each provider the house is wired with, what its adapter spells of a policy and the model names verified with it -- read from the adapter's own `SPELLS`, `MODELS` and `COST` (`conductor.adapters.load`): one line `<provider> · spells <keys> · models <names> · cost <scope>`, or under `--json` one object `{provider, spells, models, cost}`; nothing when the house is wired with none. A model name absent from `models` is never refused. |
| `responses [<path>] [--last n]` | The n latest responses (default 1), newest first, the agent's alone when named: `<at>  <agent> · run <key> · #<index> · rc <c> [· <cost> USD] [· <n> launch(es)] [· denials <n>]`, then the text, each line opening on `::` behind a backslash, as `run` prints it. Under the response, one line `[launch <n>] <text>` per words of the exchange when it took several launches, or when the words differ from the answer (plan fixes2). |
| `messages [<path>] [--last n]` | The n latest messages sent (default 1), newest first, the agent's alone when named: `<at>  <from> -> <to> · run <key> · policy <json>` with its `tag` and `pid` when it carried them, then the text, each line opening on `::` behind a backslash. |

The engine launches nothing and reads no harness: this script is the one process that
starts a harness, and the adapter of the provider reads what it answered. No provider
flag is written here: the policy travels as data to `launch()`. `--permissions` names
what the harness may do without asking: `auto` (the default) its own judgment, the mode
of an interactive session; `strict` the rules the house's settings write, anything else
denied; `bypass` every check skipped -- for a container or a VM alone. The adapter
spells the regime or refuses it (`policy-unsupported`).

## Refusals

Refusals exit 2 and write nothing, except where the table says a response is recorded first.

| Cause | What is said |
|---|---|
| a path that is not slugs joined by `/` (`..`, a leading `/`, an empty segment, a capital), a file on the path, or a subtree that carries a machine of its own | `agent-path-invalid` |
| `add` where an instance stands already | `agent-exists` |
| `add --type <package>` | `type-unsupported` |
| a verb on a path where no agent stands | `agent-unknown` |
| `--run <key>`, `name`, `exchanges` or `stats` on a key no run wears | `run-unknown` |
| `name` with a name empty once trimmed, on two lines or of more than 60 characters | `name-invalid`, nothing written |
| `stats --json` when the engine's `-stats` rendered no JSON | `stats-unreadable` |
| a wake-up without a message | `message-missing` |
| `--heartbeat` that is not a whole number of seconds, at least 1 | `heartbeat-invalid`, nothing launched |
| `--run <key>` on a run with no session recorded | `session-missing`, nothing launched |
| a second wake-up of a run whose wake lock is held | `run-busy`, nothing launched |
| a wake-up while the machine is under maintenance | `maintenance-in-progress`, nothing launched |
| `--door` with `--run`; a door the agent's instance does not resolve | `door-on-resume`; `door-unknown` (said by the agent's `-new`) |
| `--documents` naming a root other than the run's, under `--run`; a root that is no directory | `documents-fixed`, before any launch; `documents-unknown` (said by the agent's `-new`) |
| `--message-file` naming no file | `message-file-missing` |
| `--work` on a run that has its material; a resume whose clone is gone or was pruned | `work-standing` · `workdir-missing`, nothing launched |
| a repository that cannot be cloned; its lock held past `call_lock_wait`; a material the face refuses | `work-clone-failed` · `work-busy` · `workdir-invalid`, `workdir-unsupported` |
| a push that fails after the harness | `push failed`, the response kept, exit 2 |
| `prune` without a material, over commits not sent, while a wake-up plays | `workdir-unknown` · `workdir-unpushed` · `run-busy` |
| `purge` on a key nobody knows, a date that does not read, a run the family's guardian keeps, a held run, unsent commits, a call the agent's engine holds, an engine before beta.66 | `run-unknown` · `purge-invalid` · `run-held` · `run-busy` · `workdir-unpushed` · `call-busy` · `purge-unsupported` -- nothing removed anywhere |
| `verify` on a run nobody keeps, on another family | `run-unknown` · `family-foreign` |
| `add` of a path another call is giving birth to past `call_lock_wait` | `born-busy` |
| `chat` with `--message`, `--message-file`, `--dry-run`, `--tag`, `--on-end` or `--new` | `flag-unsupported`, nothing opened |
| under `chat --json`, a command that does not read, or a kind nobody knows | a `refused` event on stdout (`command-unreadable`, `command-unknown`), the flow goes on |
| under `chat --json`, a `set` of `provider`, a value that does not parse, a key nobody knows, a permission regime the run's provider does not spell, a budget cap under an adapter whose `COST` is None | a `refused` event (`provider-fixed`, `policy-invalid`, `policy-unknown`, `policy-unsupported`, `budget-unmeasured`), the policy unchanged, the flow goes on |
| `run`/`chat --run <key>` on a run of the house (`.`) its host's LLM conducts | `run-unconducted`, nothing launched |
| `--work` on the house (`.`) | `work-on-house`, nothing launched |
| under `chat --json`, `conduct` before the run is opened; a `package` the engine refuses for another cause than a flight | a `refused` event: `run-missing`; the engine's own code and detail (`package-unpinned`, `package-base`) -- a `package` before the run, or held by the run's view (`package-in-flight`), waits instead (`pending: true`) |
| a SIGINT to this script during an exchange of `chat` | the harness ended (SIGTERM, SIGKILL after 5 s), the exchange said `interrupted` -- the last finished launch's answer kept with the error `interrupted`, nothing when none had finished; the run stands, the conversation goes on; the mark of its wake lock says `interrupted: true`, and the next wake-up opens on `[interrupted by your principal]` |
| `start` with `--json` or `--dry-run`; a child that reports nothing in time, or something else | `flag-unsupported` · `start-timeout` · `start-garbled` |
| `wait` past its bound; `wait`/`result` on a launch that added no response, on a wake-up still playing, on a run never launched | `wait-timeout` · `wake-dead` · `wake-running` · `result-missing` |
| `--run <key>` under another provider than the run's | `provider-mismatch`, nothing launched |
| `--run <key>` with neither `--provider` nor `--harness`: the run's session belongs to a caller's command, or to a provider the house is no longer wired with | `harness-required` · `provider-unwired`, nothing launched -- otherwise the resume takes the run's provider and, for each key the call does not give, its last policy |
| an answer without a session identity | `session-missing`, nothing recorded |
| `--launches` that is not a whole number, at least 1 | `launches-invalid`, nothing launched |
| a wake-up that played its `--launches` (24 unless said) without the run's passage ending | `launches-spent` -- the last response recorded, the run left standing, exit 2 |
| a run whose budget cap leaves nothing (`--max-budget-usd`) | `budget-spent` -- before an exchange nothing launched nor recorded, the run as it was; between two launches the last response recorded, the run left standing; exit 2 (under `chat`, a `verdict` and the conversation goes on) |
| a budget cap under an adapter whose cost has no scope (`COST` None) | `budget-unmeasured` -- before anything, nothing written |
| a `-new` the engine refuses at the opening (`door-unknown`, `conducted-by-invalid`) | the engine's words, nothing launched, no run |
| neither `--harness` nor `--provider` on a house wired with no adapter, or with several | `provider-missing` · `provider-ambiguous` |
| the provider's binary not on the PATH (judged after the policy, before any run is opened; a `--harness` command is not judged) | `harness-missing` |
| `--harness` without `--provider` beside it: no grammar to read the command's output in | `grammar-missing`, before anything is opened or written |
| the face refuses the provider, the policy or the reading | its own words: `provider-unknown`, `launch-unsupported`, `policy-unknown`, `policy-invalid`, `policy-unsupported`, `answer-unsupported` |
| the harness exits non-zero | `harness rc <c>`, its last lines -- the response recorded first when it answered with its identity, nothing when it wrote nothing |
| the harness exits 0 and the run did not park with a response | `the passage is not over`, the block it stands on (a step pends), the last refusal traced |
| any other call | the usage, one line |
